An incremental algorithm for repairing denial constraint violations

Author links open overlay panel, , ,
https://doi.org/10.1016/j.is.2024.102435Get rights and content

Abstract

Data repairing algorithms are extensively studied for improving data quality. Denial constraints (DCs) are commonly employed to state quality specifications that data should satisfy and hence facilitate data repairing since DCs are general enough to subsume many other dependencies. Data in practice are usually frequently updated, which motivates the quest for efficient incremental repairing techniques in response to data updates. In this paper, we present the first incremental algorithm for repairing DC violations. Specifically, given a relational instance I consistent with a set Σ of DCs, and a set △ I of tuple insertions to I, our aim is to find a set △ I′ of tuple insertions such that Σ is satisfied on I+△ I′. We first formalize and prove the complexity of the problem of incremental data repairing with DCs. We then present techniques that combine auxiliary indexing structures to efficiently identify DC violations incurred by △ I w.r.t. Σ, and further develop an efficient repairing algorithm to compute △ I′ by resolving DC violations. Finally, using both real-life and synthetic datasets, we conduct extensive experiments to demonstrate the effectiveness and efficiency of our approach.

Introduction

It is known that real-life data are often dirty, due to e.g., errors, conflicts and inconsistencies. This highlights the quest for effective and efficient data quality management, and data repairing techniques are at the core of data quality management [1], [2]. Given a relational instance I violating a set Σ of data dependencies, repairing data is to modify I for a new instance I′ such that Σ is satisfied on I′. Denial Constraints (DCs) [3], [4] are general enough to subsume many other data dependencies, e.g., unique column combinations (UCCs), functional dependencies (FDs), conditional functional dependencies (CFDs) [5], and pointwise order dependencies (PODs) [6], [7]. Therefore, DCs are well employed in data repairing for improving data quality [4], [8], [9], [10], [11], [12], [13], [14].
In the following, we first give several examples of DCs.

Example 1

Consider a sample relation instance I1 about tax data, as shown in Table 1. It contains 7 tuples, and each tuple represents a person’s information, including AreaCode (AC), Phone (P), City (C), State (St), Zip (Z), Salary (Sa) and tax Rate (R). We show some data constraints holding on I1.
(1) A UCC states that any two tuples cannot have the same values on AreaCode and Phone, i.e., the combination of AreaCode and Phone is a candidate key.
(2) An FD states that tuples with the same value on AreaCode also have the same value on State.
(3) A CFD states that if a tuple has “14808” as its value on Zip, then it must have “NY” as its value on State.
(4) A POD states that for any two tuples with the same value on State, the tuple with a larger value on Salary cannot have a smaller value on Rate.
All the above four constraints can be encoded as DCs, in a universally quantified first order logic formalism (to be formalized in Section 3).
(1) φ1: ∀tα,tβ∈R, ¬ (tα[AC]=tβ[AC]∧tα[P]=tβ[P])
(2) φ2: ∀tα,tβ∈R, ¬ (tα[AC]=tβ[AC]∧tα[St]≠tβ[St])
(3) φ3: ∀tα∈R, ¬ (tα[Z]=14808∧tα[St]≠NY)
(4) φ4: ∀tα,tβ∈R, ¬ (tα[St]=tβ[St]∧tα[Sa]>tβ[Sa]∧tα[R]<tβ[R])
A relation instance I is consistent w.r.t. a given set Σ of DCs, in the sense that I satisfies all DCs in Σ. In practice, data are usually frequently updated. After a set △I of tuples is inserted into I, inconsistencies w.r.t. Σ may arise and require further treatment. Note that it suffices to only consider tuple insertions since (1) tuple deletions never cause any inconsistencies; and (2) each value modification on attribute A of a tuple t can be treated as a deletion of t, followed by an insertion of another tuple t′ with the same attribute values as t except the updated value on A.

Example 2

Consider the sample incremental tax data in Table 2, with a set △I1 of three tuples. When tuples in △I1 are inserted into I1, we see data violations arise w.r.t. the four DCs presented in Example 1.
(1) Tuples s2, t3 violate φ1: they have the same values on AreaCode and Phone.
(2) Tuples s2, t3 violate φ2: they have the same value on AreaCode, but different values on State.
(3) Tuple s1 itself violates φ3: it has “14808” as its value on Zip, but “GA” as its value on State.
(4) Tuples s3, s2 (resp. t6, s2) violate φ4: in the same state, s3 (t6) has a larger salary but a smaller rate than s2.
It is prohibitively expensive to repair I+△I w.r.t. Σ from scratch, since I is known to be consistent with Σ and △I is typically (much) smaller than I. This motivates us to study incremental DC repairing techniques, to find △I′ by repairing △I, such that I+△I′ is consistent with Σ. We must take I into consideration in this process, since tuples in △I may cause violations w.r.t. tuples in I. We contend that this incremental approach brings significant benefits in terms of both efficiency and effectiveness, compared with batch approaches that repair I+△I from scratch.
Efficiency. It is very costly to detect and then repair DC violations [4], [8], [9], [10], [11], [12], [13], [14]. In an incremental approach, we can safely skip any tuple pair t, s if both t and s are in I, since I is known to be consistent with Σ. In addition, we can build auxiliary structures for I and Σ in advance, such that violations caused by any tuple t in I and tuple s in △I can be more efficiently identified. This is possible because I and Σ are already known.
Effectiveness. Attribute values in the clean instance I may be mistakenly modified if we directly apply existing batch repairing techniques to I+△I, while the incremental approach can avoid this flaw. Moreover, the clean instance I can be employed to help repair △I, in a similar spirit of the master data [15]. Putting these together, we can expect to achieve better repair quality with incremental repairing methods.
Contributions. In this paper, we make a first effort to tackle the problem of incrementally repairing DC violations.
(1) We formalize the problem of incremental data repairing with DCs, in response to a set △I of tuple insertions to an instance I that satisfies a set Σ of DCs. We prove that this problem is NP-complete (Section 4).
(2) We propose effective techniques for incrementally detecting DC violations incurred by △I (Section 5). Based on the known clean instance I and Σ, we build auxiliary indexes to facilitate the detection of violations between tuples from I and △I.
(3) We present an incremental repairing algorithm for DC violations (Section 6). It resolves DC violations by fixing detected conflicts incurred by △I. It only modifies values in △I and always tries to infer correct values leveraging values in the clean instance I when possible.
(4) Using both real-life and synthetic data, we conduct extensive experiments to verify the effectiveness and efficiency of our methods (Section 7). Experimental results show that our approach is significantly more efficient and effective than batch repairing methods that compute from scratch.
In addition, we discuss related works in Section 2, review basic notations in Section 3 and draw conclusions in Section 8.

Conclusions

In this paper, we make a first effort to study the problem of incrementally repairing DC violations, with a clean instance I w.r.t. a set Σ of DCs, and a set △I of tuple insertions to I. We have formalized the problem, studied its complexity, provided techniques for identifying violations incurred by tuples s∈I and t∈△I with indexing techniques, developed the first incremental DC repairing algorithm, and experimentally verified our approach with both real-life and synthetic data.
